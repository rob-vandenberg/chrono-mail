# D-318 The right-click menus of a calendar event
Topics: [[calendars-contacts-tasks]]

(The owner) An event has two menus, the same in the day, week, month and Agenda views; there is no third. Invited: Edit…, separator, Accept, Tentative, Delegate…, Decline, separator, Cancel, Restore, separator, Delete. Self-created: Edit…, separator, Cancel, Restore, separator, Delete. New stays on an empty space only. Edit… is the first item (the owner, 4.4.576: leaving it out was a mistake); it opens the event ready to change ([[D-312]]), greyed for a Cancelled event (Restore it first) and in a read-only calendar.

(The owner) Greyed, by the date right-clicked: Edit… when Cancelled; the answer you gave; all four answers while Cancelled, you Restore first; Cancel when Cancelled or hidden; Restore unless Cancelled; everything in a read-only calendar, with a hover text. The commands refuse the same (OR-4).

(The owner) "This occurrence or all occurrences?" comes after the click, with both choices, and All does all. An answer on one date of a series declined as a whole in Local Folders moves the whole series to the calendar you pick, as one record: that date has the answer, the rest stays declined.

(The owner) In a calendar shared with you with write access the menu works: Accept and Tentative show the calendar dialog, Cancel, Restore and Delete act on that event. Only your own calendars are searched for a copy. A read-only calendar stays greyed.

How it is built (not the owner's words): an answer from the calendar is refused when that date has it already; on All only when every date has it, so a date answered otherwise can still be brought in line. An answer from a card is not refused. An invitation with no organizer that you declined counts as invited, as it can be answered again. The Edit button of the toolbar stays. The details file has why.

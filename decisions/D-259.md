# Hostile input is never fatal
Topics: [[mail-window]] · [[security]] · [[imap]]

(batch 4, RV-34, RV-167) **Hostile input never stops the program and is never markup.** A date in a mail outside 2 January of year 2 to 30 December 9998 (UTC) is unreadable, like a garbled one. Every message box shows plain text; the status line is plain text. An IMAP message the server refuses or sends as NIL is a passing failure. JSON nested without end is damaged, never a crash. Why: one received header stopped the mail check and every index rebuild; folder names and server replies could change what a box shows.
